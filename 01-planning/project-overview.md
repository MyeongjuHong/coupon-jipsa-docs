## 🔗 ID 체계 안내 (추적성)

## 🎯 프로젝트 목표

- 이 프로젝트를 왜 시작했는가: 가족끼리 기프티콘 공유하려고
- 해결하고자 하는 문제: 만료일 알림, 만료 기한 순 정렬
- 성공의 기준 (측정 가능한 형태로 작성)

| 성공 기준         | 측정 방법/목표 수치                         |
| ----------------- | ------------------------------------------- |
| 만료 알림이 잘 옴 | 만료 3일 전 알림 발송 성공률 100%           |
| 기한 정렬이 잘 됨 | 정렬 정확도 100%, 목록 로딩 1초 이내,       |
| 보안이 잘 됨      | 기프티콘 코드 암호화 저장, 멤버 외 접근 0건 |

## 🏆 기능 우선순위 (MoSCoW)

| 우선순위            | 기능                                                                 | 비고                                   |
| ------------------- | -------------------------------------------------------------------- | -------------------------------------- |
| Must (필수)         | 수동 입력, 카카오 연동 이메일 알림, 삭제                             | 무료티어로 스페이스 멤버 전체에게 발송 |
| Should (중요)       | 검색/필터, 카테고리 분류                                             |                                        |
| Could (있으면 좋음) | OCR 자동인식, 카카오 알림톡 연동, 알림 수신용 이메일 별도 설정, 댓글 | v0.2 이후, 사업자등록 완료 시          |
| Won't (이번엔 제외) | 결제, 마켓/거래                                                      |                                        |

## 🧭 전체 의사결정 하이라이트

> 프로젝트 전체를 관통하는 굵직한 결정만 여기에 요약. 세부 내용은 각 단계 페이지의 Decision Log 참고.

| ID    | 결정 사항                                                                                     | 이유                                                                                                                     | 관련 단계 |
| ----- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | --------- |
| DEC-1 | 기프티콘 사용 완료 상태는 전역 관리, 사용자 표시는 멤버십 기준으로 익명화                     | 실제 사용자 그대로 보여주는 대안 있었으나 타 스페이스에 낯선 이름 이슈 고려해 비멤버는 소유자(스페이스 내 닉네임)로 표시 | 기획/설계 |
| DEC-2 | 만료 알림은 v0.1 이메일로 스페이스 멤버 전체 발송, 카톡 알림톡은 사업자등록 후 v0.2로 연기    | 알림톡은 사업자등록 필수라 현재 기술적으로 불가, 이메일은 무료 티어로 전체 발송 가능                                     | 기획      |
| DEC-3 | 스페이스 초대는 링크(만료시간 24h, 1회성), 방장 승인 후 정식 멤버 등록                        | 무제한 링크 유출 리스크, 금융성 아이템 특성상 만료/1회성/승인 절차 추가                                                  | 기획      |
| DEC-4 | 카카오 이름 기본값 (개인 설정 페이지에서 수정) 스페이스 참여 시 별도로 스페이스별 닉네임 설정 | 첫 로그인 여부 판별 로직 회피(까다로웠던 경험) 스페이스마다 다른 익명성 충족                                             | 기획      |
| DEC-5 | 만료 알림은 카카오 연동 이메일로 발송(수정 불가) 알림용 이메일 별도 설정은 could로 이월       | 별도 이메일 필드 추가시 DB 컬럼 + 검증 UI 추가로 일정 지연 리스크, 카카오 이메일만으로도 알림 기능 가능                  |           |

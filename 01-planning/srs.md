## 2. 개요

### 2.1 목적

> 이 문서(및 프로젝트)가 왜 필요한지 한두 문단으로 작성

소규모 그룹(가족, 지인 등) 쿠폰 관리의 비효율성(개별 관리, 만료일 추적 어려움, 기한 초과) 개선

쿠폰 통합 관리, 자동 알림, 상태 추적

### 2.2 범위

- 포함 범위: 수동 입력, 카카오 연동 이메일 알림, 삭제, 정렬, 사용여부 카테고리화
- 제외 범위: 앱 결제, 마켓 등

### 2.3 용어 정의

| 용어     | 정의                                    |
| -------- | --------------------------------------- |
| 스페이스 | 기프티콘 공유 그룹 (가족/친목 등)       |
| 쿠폰     | 상품권, 기프티콘, 멤버십(만료일없음) 등 |
|          |                                         |

## 6. 제약사항

- 기술적 제약: 1인 풀스택 개발, 무료/저비용 인프라 우선(Supabase 등 무료 티어 활용)
- 일정 제약: 2주 내 v0.1 MVP 완성 목표 (시장 검증 우선)
- 예산 제약: 월 운영 비용 최소화 (서버비, 이메일 발송 등 무료 티어 범위 내)
- 규정/정책: 개인정보보호법 준수, 카카오 OAuth 약관 준수, 이메일 발송 서비스 스팸 정책 준수

## 7. 가정 및 의존성

- 가정:
  - 사용자(가족/지인)가 정기적으로 이메일 확인
  - 모바일 웹 기반 접근 환경 (v0.1 기준 앱 미지원)
  - 그룹 내 기본적인 신뢰도 존재 (승인 시스템으로 보안 보완)
- 외부 의존성(API, 라이브러리 등):
  - 카카오 OAuth API (인증)
  - 이메일 발송 서비스(SendGrid, Resend 등)
  - 클라우드 DB/호스팅 (SupaBase, flare pages등)
  - Node.js/TS, Next.js, Prisma 등 기술 스택

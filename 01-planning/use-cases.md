## 3. 유스케이스 상세

### **UC-001:** 카카오 로그인

**액터: 신규/기존 사용자**

**목적(Goal):** 카카오 계정으로 서비스 진입

**사전 조건(Precondition):** 카카오 계정 소유

**기본 흐름(Basic Flow):**

1. 사용자가 로그인 버튼 클릭
2. 카카오 인증 페이지로 리다이렉트
3. 사용자가 카카오 계정 인증
4. 개인 스페이스 자동 생성 (백그라운드)
5. 1. 일반 가입: 개인 스페이스 진입
   2. 초대 링크로 가입: 팀 스페이스 입장신청 화면 (DEC-6)

**사후 조건(Postcondition):**

- 인증된 세션 유지
- 개인 스페이스 생성 완료
- 팀 스페이스 목록 조회 가능

**대체 흐름(Alternative Flow):**

- A1. 이미 회원인 경우 → 로그인 후 개인 스페이스로 이동 (마지막 접근 스페이스는 추후 고려)

**예외 흐름(Exception Flow):**

- E1. 카카오 인증 실패 → 에러 메세지 표시 + ‘다시 시도’ 버튼
- E2. 개인 스페이스 생성 실패 → 재시도 로직 (최대 3회)
- E3. 초대 링크 만료 → ‘만료된 초대입니다’ 메세지 + 개인 스페이스로 이동

**관련 화면:** 로그인 화면 → (카카오 인증) → 개인 스페이스 또는 팀 스페이스 입장 신청

### **UC-002:** 스페이스 멤버 초대 및 승인

**액터:** 스페이스 방장

**목적(Goal):** 초대 링크 생성 → 멤버 신청 수집 → 승인 (그룹 스페이스로 쿠폰 공유)

**사전 조건(Precondition):** 스페이스 소유자 로그인 상태

**기본 흐름(Basic Flow):**

1. 방장이 ‘새 스페이스 생성’ 버튼 클릭
2. 스페이스 이름 입력 후 생성
3. ‘멤버 초대’ 버튼 클릭
4. 24시간 유효 초대 링크 생성 (1회성) (DEC-3)
5. 방장이 링크 공유 (카톡/문자 등)
6. 초대받은 사용자가 링크 클릭 → ‘가입 신청’ 상태로 대기
7. 시스템이 방장에게 신청 알림 (이거도 이메일 알림이 필요할듯? 또는 서비스 내 알림으로..)
8. 방장이 신청 목록에서 승인 → 정식 멤버 등록

**사후 조건(Postcondition):**

- 팀 스페이스 생성 완료
- 멤버가 스페이스 내 쿠폰 조회/추가/수정 권한 획득

**대체 흐름(Alternative Flow):**

- A1. 초대 링크 만료 전 다른 링크 재생성 가능 → 기존 링크는 자동 만료

**예외 흐름(Exception Flow):**

- E1. 초대 링크 만료 → ‘초대 기간이 지났습니다’ 메세지
- E2. 방장이 신청 거절 → 사용자는 개인 스페이스에서만 이용 가능
- E3. 네트워크 오류 → 재시도 옵션

**관련 화면:** 스페이스 관리 화면 → 초대 링크 생성 → 신청 목록 → 승인/거절

### **UC-003:** 쿠폰 등록, 조회, 정렬

**액터:** 스페이스 멤버

**목적(Goal):** 쿠폰 정보 등록 → 만료순 정렬된 목록 조회

**사전 조건(Precondition):** 스페이스 접근 가능한 멤버 상태

**기본 흐름(Basic Flow):**

1. 사용자가 쿠폰 추가 버튼 클릭
2. 등록 폼에 (이미지, 브랜드명, 금액, 만료일) 입력
3. 등록 클릭 → 쿠폰 등록 완료
4. 목록 화면 자동 새로고침
5. 만료일 임박순 정렬로 조회됨 (기본값)
6. 사용완료 버튼 클릭 → 상태 변경

**사후 조건(Postcondition):**

- 쿠폰이 스페이스 목록에 표시
- 모든 멤버가 조회 가능
- 소유자는 DB에 기록, UI는 익명화 (DEC-1)

**대체 흐름(Alternative Flow):**

- A1.

**예외 흐름(Exception Flow):**

- E1. 이미지 업로드 실패 → ‘이미지를 다시 업로드해주세요’ + 재시도
- E2. 만료일 형식 오류 → 날짜 형식 안내 후 수정 가능
- E3. 네트워크 오류 → 로컬 캐시 유지 + 재시도

**관련 화면:** 스페이스 목록 → 쿠폰 추가 폼 → 쿠폰 목록 (만료순 정렬)

### **UC-004:** 만료 알림 발송 (시스템 프로세스)

**액터: 시스템**

**목적(Goal):** 만료 예정 쿠폰 정보 메일 발송

**사전 조건(Precondition):**

- 쿠폰 등록 완료
- 사용자 이메일 보유

**기본 흐름(Basic Flow):**

1. 시스템이 매일 자정에 쿠폰 만료일 체크
2. 만료 7일 전 사용자에게 이메일 발송 (DEC-2)
3. 만료 1일 전 재차 이메일 발송
4. 사용자가 메일 수신

**사후 조건(Postcondition):**

- 이메일 발송 완료 로그 기록
- Sentry에 실패 여부 기록

**대체 흐름(Alternative Flow):**

- A1.

**예외 흐름(Exception Flow):**

- E1. 이메일 발송 실패 → 자동 재시도 (최대 3회)

**관련 화면:** (백그라운드 프로세스 - UI 없음)

### **UC-005:** 사용완료 처리

**액터: 스페이스 멤버**

**목적(Goal):** 쿠폰 사용 완료 상태로 변경

**사전 조건(Precondition):**

- 스페이스에 등록된 쿠폰 존재

**기본 흐름(Basic Flow):**

1. 사용자가 쿠폰 목록에서 쿠폰 카드 클릭
2. 상세 화면 진입
3. ‘사용완료’ 버튼 클릭
4. 상태 변경 (전역 상태 업데이트, DEC-1)
5. 모든 멤버의 화면에 반영

**사후 조건(Postcondition):**

- 쿠폰 상태가 ‘사용완료’로 변경
- 모든 스페이스에서 동일 상태 반영
- 30일 후 자동 삭제 예약 (운영 단계에서 스토리지 비용 기반 조율)

**대체 흐름(Alternative Flow):**

- A1.

**예외 흐름(Exception Flow):**

- E1. 네트워크 오류 → 로컬 상태 유지 후 재시도

**관련 화면:** 쿠폰 상세 화면

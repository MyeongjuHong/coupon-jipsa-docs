# 시스템 아키텍처

## 1. 전체 아키텍처 개요

### 시스템 다이어그램

(텍스트로 아스키 다이어그램 또는 이미지 링크)

### 설명

- **클라이언트 (프레젠테이션 계층)**: Next.js, React, TypeScript, Tanstack Query, Zustand, Zod, Tailwind CSS, Cloudflare Pages
- **백엔드 (비즈니스 로직 계층)**: NestJS, TypeScript, TSX, Helmet, CORS, JWT, Argon2, Dayjs, Nanoid, Render, fly.io
- **데이터베이스 (데이터 접근 계층)**: Prisma, PostgreSQL, Supabase
- **외부 서비스**: Kakao OAuth, SendGrid(이메일), Sentry(모니터링)

> NginX, Redis, Docker, WebSocket, RabbitMQ/Kafka 등은 v0.1 스코프에서 제외. 이유는 각 항목 하단 참고

## 3. 배포 아키텍처

| 컴포넌트         | 배포 환경        | 선택 이유                                           | 트레이드오프                                                                     | 비고                                                                                             |
| ---------------- | ---------------- | --------------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **프론트**       | Cloudflare Pages | 무료 티어에 Vercel은 안되는 상업적 이용까지 가능    | Next.js 돌리려면 `next-on-pages` 어댑터 필요, Vercel 대비 Next.js 특화 기능 제한 | 트래픽 증가 시 Vercel Pro 재검토                                                                 |
| **백엔드**       | Render           | 무료티어 존재, 자동 배포 지원                       | 콜드스타트 있어 cron 필요, 동시 요청 몰리면 응답 지연 (512 RAM, 공유 CPU 제한)   | 실사용자 확보 후 Fly.io 마이그레이션 검토                                                        |
| **데이터베이스** | Supabase         | 무료티어 존재, 스토리지와 동일한 계정으로 관리 가능 | 7일 미사용 시 자동 일시정지, RDS 대비 리전 선택지 적음                           | Render 헬스체크 cron에 Supabase 쿼리 포함 (주 2회), 무료티어 사용으로 중요 데이터 별도 수동 백업 |
| **스토리지**     | Supabase Storage | 무료티어 존재, DB와 같은 계정으로 관리 가능         | S3 대비 성숙도/안정성 낮고 세밀한 IAM 제어 약함                                  | 이미지 용량 증가시 AWS S3 마이그레이션 검토                                                      |

### 배포 흐름

```markdown
GitHub Push (main 브랜치)
↓
프론트: Cloudflare Pages가 push 감지 -> 자동 빌드(next build) -> 자동 배포
백엔드: Render가 push 감지 -> 자동 빌드(npm install, build) -> 자동 배포
↓
프로덕션 배포

> 별도 CI/CD 파이프라인(GitHub Actions 등)은 v0.1에서 불필요
> 두 플랫폼 모두 Git push 기반 자동 배포를 기본 제공
> 테스트 자동화(v0.2, Vitest 도입) 이후 '빌드 전 테스트 실행' 단계 추가 검토
```
